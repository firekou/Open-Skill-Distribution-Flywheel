# ATK Evidence-Driven Execution Doctrine v1

**Status:** Governing execution doctrine

## Core principle
**大膽假設，小心求證。** Vision can be large; evidence cannot be loose.

## Purpose
This repository is a company learning system. Its purpose is to move ATK forward through:
**Hypothesis → Evidence → Decision → Execution → Feedback.**

Every meaningful task must answer: Which hypothesis is being tested? What evidence will be produced? What decision could change?

## Scope
Start from Token as the first measurable wedge into the Agent economy. Current scope includes Token efficiency, Agent unit economics, measurement, attribution, trust, routing, context/memory, MCP/tool economics, skills/frameworks, A2A, security, identity, governance, billing, budgets and payments.

Long-term frame: **Know what Agents are doing → Measure what Agents consume → Control how Agents spend.**

Commercial frame to test: **Media → Intelligence → Measurement → Execution.**

## Research doctrine
1. Bold hypotheses are encouraged.
2. Important hypotheses require active counterevidence search.
3. Model agreement is not evidence.
4. Resolve disagreement with primary evidence, experiments and reproducibility.
5. Keep vision large and the next validation step small.
6. Preserve negative results.

## Evidence ladder
**REPORTED → OBSERVED → TESTED → VERIFIED → REPRODUCED**

## Hypothesis confidence
**H0 Idea → H1 Signal → H2 Supported → H3 Tested → H4 Validated → H5 Commercially Proven**

Stars, views and model consensus cannot by themselves produce H5.

## Foundational hypotheses
H001: Agent scale increases demand for Measurement / Attribution / Trust.
H002: Token Cost is a strong wedge into Agent Resource Intelligence.
H003: Technical Intelligence Magazine can become a low-CAC distribution and trust engine for ATK.
H004: An Agent-native multi-model organization can materially increase verified reusable output per human hour.
H005: As AI makes information generation cheaper, trustworthy evidence, reproducibility and verification become more valuable.

Derived research: H006 Agent Unit Economics; H007 Cost per successful task; H008 Quality-adjusted routing; H009 Trust Receipts; H010 Human + Agent demand sensing.

## Three ledgers
Maintain Hypothesis, Evidence and Decision Ledgers. A decision without traceable evidence must be marked **STRATEGIC BET**.

## Progress gates
G0 Question → G1 Hypothesis → G2 Signal → G3 Research + counterevidence → G4 Test Design → G5 Execution → G6 Verification → G7 Decision → G8 Distribution → G9 Demand Feedback → G10 Productization.

Do not silently jump gates.

## Forward-Motion Rule
Every major Agent run ends by answering:
1. What uncertainty was reduced?
2. Which hypothesis changed confidence?
3. What new evidence was produced?
4. What failed or contradicted us?
5. What decision is now justified?
6. What is the single next gate?
7. What requires Editor-in-Chief/ChatGPT review?

If these cannot be answered, the work is incomplete.

## Multi-model convergence
Claude primarily executes and produces. ChatGPT primarily strategizes, reviews and red-teams. Other models may independently research, code or challenge. The human Publisher/Editor-in-Chief allocates direction and resources.

Do not seek model consensus first. Record disagreement and convert it into testable questions.

## Permissionless doctrine
Seek leverage in Research, Production, Publishing, Distribution and Productization. Permissionless does not mean ignoring licenses, attribution, security, privacy or platform rules.

## Magazine operating loop
ATK Intelligence discovers. ATK Verify controls evidence state. ATK Lab experiments. ATK Benchmark compares. ATK Magazine distributes. Demand Intelligence measures response. ATK Engineering productizes validated opportunities.

**Signal → Research → Proof → Content → Distribution → GitHub → Demand → Decision → ATK**

## Anti-wandering rules
Do not expand scope because something is merely interesting. Do not create a strategic pillar without a hypothesis ID. Do not create documents with no decision use. Do not equate popularity with users. Do not treat vendor claims as ATK verification. Do not research indefinitely after a decision threshold. Do not run expensive benchmarks before methodology review. Do not build before evidence, rights and security gates.

Progress is not more files, agents, posts, forks or autonomous runs.

Progress is **less uncertainty + stronger evidence + better decisions + reusable verified assets + measurable demand + validated product learning.**
