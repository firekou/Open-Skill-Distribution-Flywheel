# 執行回報 Skill — 四節強制格式

> **來源：** 負責人 2026-09-26 直接指定，並以「一定、一定、一定、一定要遵照」強調。
> **語言：** 繁體中文。
> **適用：** 所有專案、所有執行動作、所有 agent。**沒有例外。**

---

## 為什麼要有這個 skill（先讀這段，否則會寫成流水帳）

這個格式不是為了讓報告好看，是為了讓**「沒有進度」這件事沒辦法躲在工作量後面**。

它要解決的具體病灶（皆為實際發生過的）：

| 病灶 | 這個格式怎麼擋 |
|---|---|
| 做了很多事，但看不出到底前進了沒有 | 第 2、3 節強迫直接回答「有沒有前進」 |
| 用「我做了 A、B、C」冒充進度 | 明文禁止以工作量充當進度答案 |
| 把結論講得比證據強（例如把 4 個瞬間說成持續一小時） | 第 2 節要求寫出困難與卡點，第 4 節要求用大白話講「換到了什麼」 |
| 說某件事改好了，實際只改在別的檔案裡 | 第 1 節要求指名誰做了什麼，可被回查 |
| 報告堆滿代號，負責人得自己拼 | 第 4 節禁止代號與術語堆疊 |

**判準只有一條：讀完之後，負責人能不能一句話說出「這次前進了還是沒前進」。** 不能，就是沒寫好。

---

## 固定格式（照抄，四節都要）

### 1. 執行者

- 哪些 agent 完成了這件事？經過了哪些 agent？誰執行的？
- **只有單一 agent 就明講「只有我，沒有經過其他 agent」。**
  不得含糊，**更不得虛構有 agent 參與**。
- 有分工就列出誰負責哪一段（executor／reviewer／Controller／各專業 agent）。
- 有產出就列出 repo、分支、commit SHA，讓每一句都能被回查。

### 2. 小目標進度

- 此次執行是往哪一個小目標前進？屬於哪一個小目標階段？
- **有沒有真的往前進？沒有就寫「沒有前進」。**
- 遇到什麼困難？
- 卡在哪裡需要決策？**要指名需要誰決策**（負責人／Controller／某個 agent／外部）。
- 缺乏什麼資訊？沒缺就寫「沒有」。

### 3. 目標藍圖對齊

- **每次都要重新寫出現在的目標藍圖是什麼。**
  不得只寫「同上」、不得只丟連結、不得只寫階段代號。
- 是否遵照藍圖前進？
- 距離藍圖的方向有沒有前進？
- 目前處在藍圖的哪一個階段？

### 4. 本次執行的意義

- **用大白話寫。** 不用代號、不用縮寫、不用術語堆疊。
- 要讓**沒有讀過前面任何一份文件的人**也看得懂「這次到底換到了什麼」。
- **不得是第 2 節的重複。** 第 2 節答「進度在哪」，第 4 節答「所以這對人有什麼用」。

---

## 紀律（違反即視為回報未完成）

1. **四節缺一即未完成。** 不得合併、不得省略、不得改名、不得因為「這次很小」而跳過。
2. **被擋住也要照格式回報。** 「還在等授權」「被權限擋住」「沒有結果」一樣要寫完四節。
3. **沒進展要寫沒進展。** 第 2、3 節不得用做了哪些事來冒充前進。
4. **第 4 節不得重複第 2 節。**
5. **不取代既有格式。** 各專案原有的完工／PR／送審格式照舊都要寫
   （例如 DeFiLab `CLAUDE.md` §3 的 Validation 區塊）。兩者並存。
6. **不得虛構執行者。** 沒有其他 agent 參與就說沒有。
7. **每一個可查證的東西都要給得出出處** —— SHA、檔案路徑、行號、命令與退出碼。
8. **證據強度要誠實標記。** 未實測就寫未實測；「讀不到」不等於「不一致」；
   HTTP 200 不等於讀成功；查不到就寫未量測，**不得寫 0**。

## 自我檢查（送出前跑一遍）

```text
[ ] 1、2、3、4 四節都在，標題沒被改名
[ ] 第 1 節有指名執行者；沒有其他 agent 就明說「只有我」
[ ] 第 2 節有直接回答「有沒有前進」，不是列工作量
[ ] 第 2 節有指名「需要誰決策」
[ ] 第 3 節重新寫出了完整藍圖，不是「同上」或只給連結
[ ] 第 3 節指出了目前在哪一個階段
[ ] 第 4 節是大白話，沒有代號，且不是第 2 節的複述
[ ] 每個可查證的主張都有 SHA／路徑／命令
[ ] 沒有把「沒跑」寫成「通過」
```

**最後一條最重要：把「沒跑」寫成「pass」是最嚴重的紀律事故 ——
因為讀報告的人會據此決定要不要把錢放進去。**
