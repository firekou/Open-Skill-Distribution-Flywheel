## 1. 終點與責任
負責人要求先規劃全部藍圖與終點。本文件一次定義研究、引入、接入、分發、使用、貢獻、經濟回收和維護的全程；之後每輪只執行其中一個可驗收工作包，不再每做一步才猜下一步。
最終成果：開源開發者與其 Agent 能從我們的公開技術資產完成真實工作，自由選擇 ATK；實際再次使用，且我們能說明比直接用上游多提供了什麼，以及維持服務是否划算。
「有人應該用」不是結論。沒有增量，就推薦上游、撤下無效改造；這也是有價值的裁決。

五個終點分開驗收：
1. 使用者：完成真實任務、品質達標、學習與排錯負擔合理、能自行再次完成。
2. 技術資產：固定版本可跟做、可選 provider、邊界與失敗可查、有人維護。
3. 開源公共價值：可重用案例、可重現反例、教學或修正被外部使用或確認；原作得到正確歸因。
4. ATK：有可核對的活躍專案、重複使用與淨貢獻；接入可用不等於有使用價值。
5. 組織能力：研究能改變選擇、失敗能停止、交接能續作；治理只支援上述結果。

## 2. 產品邊界與使用者
第一客群：正在處理小型程式修正的開源開發者與其 Agent。
第一場景：Aider 原生設定完成一項有固定測試的程式修改；沿用 PR14，不新造 SDK。
第二場景：有長部署／CI log 分析需求者；Headroom 為已存在資產，需求不匹配就不邀請。
後續場景：可重用工作 skill、單一既有工具整合、必要的任務狀態／記憶接點。每項需先有需求證據。
Router/API 是現有模型接點；MCP 只在使用者要由 Agent 調用工具且原生接點不足時使用。三者不是必須各做一套的交付清單。
不建立通用評測平台，不重啟 Freeze 或 Omnigent/AGT/OMA 試點，不把跨 ATK 全組織所有產品納入本 repo。

## 4. 研究室如何工作與學習
不是蒐集排行榜。每個批次先寫使用問題，再查官方 release/論文/code/issues、獨立重現、GitHub/GitLab 下游整合及反例。
範圍雷達涵蓋模型/推理、agent/skill、API/MCP、routing、RAG/記憶、評估與開源治理；每批列覆蓋與未覆蓋範圍，不聲稱看完所有 AI。
每批最多三個深入候選、一個實作；現有 Aider 是第一項，不重挑三個來取代已完成工作。

候選卡包含：作者/原作貢獻、真實受益者、來源日期與 SHA、code/weights/data/eval recipe 開放範圍、授權、維護與安全、現有替代方案、第三方正反效果、成本、我們可以直接學用的部分、增量假說及反證。
評選順序：需求匹配 → 原作可直接使用程度 → 可確認效果 → 接入與維護成本 → ATK 適合度；不按 stars 加權排名。
stars 與引用只觸發深讀：引用是在使用方法、比較、背景提及還是反駁？star 使用者動機不明就記未知。
引入裁決只選一個：直接用原作、改善文件、薄接入、必要的小修正、不採用。另造平台需要新的具體必要性。

學到的每項方法都要連到交付：例如將逐案例證據、失敗分類、配對比較用到 Aider 任務；不是再寫一套評估框架。
外部方法參照：既有研究文件保存 Inspect/Pydantic/HELM 等來源。2026-09-26 再查 Aider 官方相容 API 文件與 CHAOSS viability 指引；前者已有原生端點設定，後者涵蓋社群、治理、策略、合規/安全，因此原生接入與可維護性優先於自造 adapter。
來源：
- https://aider.chat/docs/llms/openai-compat.html
- https://www.chaoss.community/practitioner-guide-viability/
- research/AI_LAB_EXTERNAL_CONTRIBUTIONS_2026-09-24.md
以上為方法來源，不代表第三方背書 ATK，也不代表本輪執行新模型實驗。

## 5. 價值怎麼驗，而不是自己驗自己有用
|層級|驗什麼|對照與證據|不能代替它的東西|
|---|---|---|---|
|運作|實際完成指定任務|固定輸入、版本、真模型結果、不可由模型修改的測試、人工語意檢查|mock、設定檢查通過|
|我們的增量|比直接使用原作少了什麼困難|同等任務/環境/模型配置，比首次成功時間、錯誤、人工協助、總成本|把上游能力算成我們貢獻|
|外部效用|非作者是否能完成、是否願意再次用|經同意的去識別逐次紀錄、失敗/拒用原因、再次使用證據|內部 AI review、邀請、stars|
|公共價值|誰重用了什麼、減少什麼負擔|外部重現、下游 commit、維護者確認、教學跟做記錄|PR 數、文件數|
|ATK 回收|活躍專案與可持续淨收益|同意範圍內的用量/帳務、支持工時、服務成本、重複使用|註冊、點擊、API 呼叫量本身|

先固定成功條件、基線、最低有用差異與不可退步項，再測；小樣本報個案，不宣稱普遍提升。
Aider 初次探索：原生文件 vs ATK 指引，使用等難度小任務、平衡先後順序；最低有用差異在招募前依任務時間/支援負擔訂出，不事後挑勝出的指標。品質底線是任務測試與人工檢查均達標、無未授權修改。
淨工時改善 = 基線工時 − 使用後工時 − 額外學習/接入/維護攤提；不虛構時薪。
經濟結果 = 可歸因實收 − provider 成本 − 其他變動成本 − 明示假設的支援成本。沒有帳務只記未知。
分母保留所有嘗試者，失敗/退出不得刪；無參與同意不收私人程式碼、log 或身份資料。
