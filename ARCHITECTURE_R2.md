# ATK Technical Intelligence & Distribution Engine — Architecture R2

## Mission
The repository's primary job is no longer "find things to fork". Its primary job is to continuously discover useful AI technical material, understand it, test it when useful, turn it into distributable knowledge, and only then decide whether integration or forking is warranted.

## Core flywheel
Discover → Understand → Classify → Test → Contentize → Distribute → Observe → Discover

Integration is a branch, not the entrance:
- Research
- Tutorial / commentary
- Companion adapter
- Fork / redistribution
- Deep ATK integration

## Three lanes

### Lane A — Discovery & Material Intelligence
Purpose: maximize high-quality technical raw material.
No fork approval, maintainer assignment, security review, or redistribution license is required merely to catalogue and analyze a public source. Record source, provenance and usage constraints.

Target domains:
MCP, A2A, Agent Frameworks, Skills, AI SDKs, Routing, Model Gateways, Context Engineering, Memory, Tool Use, Browser/Computer Use, Coding Agents, multimodal agents, workflows, evals, observability, identity, payments, token/cost optimization, RAG, multi-agent and agent security.

### Lane B — Content & Distribution
Turn qualified material into technical material cards and content opportunities for ATK-owned social distribution.
Outputs may include analysis, tutorials, comparisons, experiments, Threads/X/LinkedIn briefs, blog briefs and video briefs.
Always preserve source attribution. Do not copy protected content beyond what is legally permitted.

### Lane C — Integration & Redistribution
Only candidates selected for code modification, redistribution, bundling or commercial distribution enter the existing License Gate, Security Review, Maintainer Gate, Fork Policy and Upstream Sync process.

## Critical policy correction
**License Gate is a redistribution gate, not a discovery gate.**

A license failure means "do not fork/redistribute under the proposed model." It does NOT mean "ignore this project as technical intelligence." Such projects can remain discovery sources, research references and tutorial subjects where lawful.

## Action taxonomy
Every material must receive one or more actions:
1. research
2. content
3. tutorial
4. experiment
5. link_upstream
6. companion_adapter
7. fork_candidate
8. deep_integration

## Operating target
Daily/periodic scout:
100 signals → deduplicate → 30 qualified materials → score → Top 10 opportunities → 5 content briefs + 2 experiments + up to 1 integration candidate.

Do not force quotas when quality is insufficient.

## Success metrics
Primary discovery metrics: qualified materials/week, source diversity, freshness, technical usefulness.
Distribution metrics: impressions, clicks, saves, GitHub visits, returning audience.
Integration metrics remain MAAPP, API activation and attributable token consumption.

The system must never optimize only for forks or stars.
