## 一句話

**「每個成功任務花多少」這個問題，多數團隊卡在的不是算不出來，是算出來的東西沒人驗過分母。**

## 四個已經量到的破口

**① 價目表本身就可能是殘缺的。** 同一張快照上，15 個費率有 **12 個沒有 cached input 價**——缺的是全部 OpenAI 與全部 Anthropic 型號（`C-001`，TESTED）。計量器的正確反應是**拒絕計價**，不是把快取 token 用未快取費率折進去。

**② 兩個方向的誤差都很大，而且方向相反。** 在對抗性校準案例上，只記錄被接受那一次呼叫的計量器**低估 65%**；把 cached token 以未快取費率計價則**高估 5.41 倍**（`C-002`，TESTED）。這兩個錯誤不會互相抵銷，它們發生在不同的流量形狀上。

**③ 位元組除以四不能救。** 同一份 fixture 上，該估算器誤差 **13.6% 到 61.0%，而且會變號**（`C-003`，TESTED）。**沒有任何校正係數能修好一個誤差隨輸入而變的估算器**——這是結構性結論，百分比本身是合成值不得外引。

**④ 價格倍數是配對方式的函數。** 同一組牌價，換一種配對會從 **11.4 倍**變成 **257 倍**。ATK 自己先前 published 的「約 100 倍」是挑選費率層級的結果（`C-004`，OBSERVED）。DeepSeek 一個型號就有四個 input 價（快取命中／未命中 × 尖峰／離峰）。

## 為什麼這不是吹毛求疵

一個 80,473 星的節省工具，其使用者提出的重現案例顯示節省量被**高估逾一萬倍**（`C-005`，OBSERVED）。
限制要一起讀：14 則 issue 對 80,473 星是抱怨者偏誤樣本，而且「想要準確數字」不等於「願意為可驗證的計量付費」。

## 本篇自己的分母

本 repo 目前唯一跑完的十筆紀錄是 dry run，token 數來自**以 task id 為種子的偽隨機數**；那次執行對 token 最佳化**不建立任何結論**（`C-006`，TESTED）。

**本篇沒有任何一項是第三方工具的效果量測。** 五條證據全部關於我方自有的計量與環境。失敗與重試的成本、人工時間的成本，本篇只有結構性論證，**沒有數字**。
