## 三類證明分別報告
| 證明 | 本專案須能看到的結果 | 不能替代它的東西 |
|---|---|---|
| 運作證明 | 固定版本依 Quick Start 真正完成指定任務；保存實際輸入、命令、輸出、成功／失敗、環境與時間。若主張持續服務，再保存運行窗口、最新成功時間、故障與重啟恢復 | 文件完成、PR 建立、CI 綠燈、mock 或一次執行不能證明持久服務 |
| 使用價值證明 | 使用者或其 Agent 完成原本的工作；記任務答案／關鍵資訊是否正確、耗時、成本、人工協助及適用限制。效果比較綁同一輸入與條件 | 單一縮小百分比、工具星數、內部測試或邀請已寄出，不能證明外部有用 |
| 經濟成果證明 | 有真實用量、持續使用、可歸因收入與成本時，提供期間、原始紀錄及對帳；沒有就記未驗證 | 曝光、預估收益、模擬節省、免費採用不等於收入或已實現獲利 |

DeFi／套利先前討論的實際成交與對帳要求，在本專案對應實際使用、可歸因收入與成本；不將交易任務引入本 repo。一般工具不需要先建持久服務才能交付；只有主張「持續運作」才驗對應持續性。

## 最小可確認成果
下一個已授權執行批次，優先讓一個明確使用者／Agent 從固定入口走完一個真實任務，留下可重播結果。合成資料可驗功能，須標明合成；外部採用須有非作者實際使用證據。
每批先定成功條件與停止點：例如能正確找出指定部署 log 的失敗 migration 與 SQLSTATE；壓縮節省只在相關測量成立時報告。失敗、無效、無節省亦為結果，不挑選成功樣本。
有授權且具備所需條件就直接完成可用小交付、必要驗證與 Draft PR，不只提交新計畫。
缺憑證先完成離線部分，真實 ATK 連線標未驗證；API、Router、MCP 逐項記實際測到的路徑，不將一條通路成功外推至全部。
已完成的小交付不因可選改善無限延後；review 只阻擋影響當前功能、安全與對外承諾的問題。

## 每次交付附上的最小證據
直接追加在既有 executor response，不另建平台：
- work_id、授權範圍、base SHA、implementation/result SHA、執行 session/run、開始／結束时间。
- 使用者類型、原始任務、事先確定的成功條件；樣本數、分母與觀察期間。
- 固定輸入版本或 checksum、環境／依賴、完整重播命令與 exit code。
- 可查看的實際輸出、原始紀錄位置／雜湊、失敗與負控制；秘密與客戶原始資料不得外洩。
- 相較上次新增的可用成果；首次成果耗時、成本、人工介入；未知填 UNKNOWN，不填假零。
- 證據分級沿用 executive-review-gate：REPORTED、OBSERVED、TESTED、VERIFIED、REPRODUCED。作者自測不自行提高為獨立通過。
- 內部測試、人工直給、受邀外部使用、目錄發現與公開搜尋發現分開；邀請數、採用數、重複使用數分開。
- 負責人可親自確認的固定連結或重播步驟，以及這項證據不能證明什麼。

## 節奏、阻礙與角色
每次回報先說「新增了什麼能親自確認的成果，證據在哪」。沒有新增成果就直說本輪未交付新運作／效果證據，列出阻礙、已嘗試方法與下一個可執行動作。
沒有新 head／證據的事件依去重規則安靜結束；此準則不要求重複發報告。
GPT 負責規劃與獨立覆核，Claude 等執行者完成實作及實跑；自己修改的實作不得自己批准。
交接直接留在 GitHub；不要求負責人搬運技術報告。留言送出不等於 session 啟動。
阻塞時具體記哪個 runtime 能力、帳號權限、授權或資料缺失，誰能解除；無依賴工作照常完成。
沿用每批最多兩輪修復，不以本準則重置上限，不啟動第三輪或平行 controller。
